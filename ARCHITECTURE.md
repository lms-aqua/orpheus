# ORPHEUS — Architecture

Structure, and the reasoning behind the decisions that would be expensive to
reverse later.

---

## 1. Shape

```text
┌─────────────────────────────────────────┐
│ ORPHEUS (app target)                    │
│  App/ DesignSystem/ Features/           │  SwiftUI, MainActor-isolated
└───────────────────┬─────────────────────┘
                    │ depends on
┌───────────────────▼─────────────────────┐
│ OrpheusCore (local Swift package)       │
│  Security/ Storage/ Models/ Support/    │  no UI, nonisolated by default
└─────────────────────────────────────────┘
```

The app target holds only UI. Everything else is a package.

**Why a package rather than folders in the app target.** Three concrete
benefits, not aesthetics:

1. The layering is enforced by the compiler. Core cannot import a view, because
   it cannot see the app module. Folder conventions rot; module boundaries do
   not.
2. Core tests are **hostless** — a unit-test bundle links the library directly
   with no app host. The cryptography suite runs without booting an app, which
   removes the single largest source of iOS CI flake.
3. Core is nonisolated by default while the app target sets
   `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`. That is exactly the right split:
   UI code wants to be main-actor by default, and encryption code must not be.

## 2. Project generation

`ORPHEUS.xcodeproj` is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)
from [`project.yml`](project.yml), and is **not committed**.

A `.pbxproj` is a machine-managed file with UUID cross-references. Committed, it
produces merge conflicts no one can resolve by reading them, and target changes
are invisible in review. As text in `project.yml`, adding a share extension or an
entitlement is a legible diff.

XcodeGen is build tooling, not an app dependency, so the "prefer Apple
frameworks" rule does not apply to it — nothing it produces ships in the binary.

## 3. Concurrency

Swift 6 language mode, strict checking, resolved properly rather than silenced.

- App target: `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` plus
  `SWIFT_APPROACHABLE_CONCURRENCY`. SwiftUI views and view models are
  main-actor-isolated without annotation noise.
- Core: nonisolated by default. Encryption, file I/O, and thumbnail generation
  must never run on the main actor.
- Value types are `Sendable`; mutable shared state uses actors.
- Warnings are reviewed. There is no global suppression, and no
  `@unchecked Sendable` used to make a real problem quiet.

## 4. Data

Split by what each store is good at:

| Data | Where | Why |
|---|---|---|
| Metadata: titles, tags, timestamps, relationships | SwiftData | Queryable and sortable without decrypting the vault |
| Content payloads and attachments | Encrypted blobs in app storage | Large, streamed, never loaded whole |
| Vault key | Keychain | The only store designed to hold key material |

Binary content stays out of the SwiftData store. Putting multi-hundred-megabyte
blobs in the model graph would make every fetch expensive and every migration
risky.

The tradeoff is explicit: metadata is not ciphertext, so titles and tags are less
protected than bodies. That is recorded in [SECURITY.md](SECURITY.md) rather than
left for someone to discover.

## 5. Encryption layering

```text
KeyPurpose            what a key is allowed to protect (domain separation)
CryptoEngine          AES-256-GCM seal/open, HKDF subkey derivation
EncryptedBlobHeader   on-disk format, parsing, validation
ChunkedCipher         streaming encryption over that format
BlobStore             where blobs live, integrity metadata, lifecycle
```

Each layer is separately testable, and the format is parsed in exactly one
place. See [SECURITY.md](SECURITY.md) for the cryptographic reasoning.

## 6. Navigation

One `TabView` with `.tabViewStyle(.sidebarAdaptable)`: a tab bar on iPhone, a
sidebar on iPad and in wide windows, resolved by the system.

The alternative — branching on `horizontalSizeClass` between a `TabView` and a
`NavigationSplitView` — means two navigation trees, two sets of state, and
duplicated bugs. Size class is also the wrong signal on iPad, where windows
resize freely.

## 7. Errors

`OrpheusError` carries user-presentable, localised descriptions and, where
something can be done, a recovery suggestion. No case embeds key material or
decrypted content, so an error cannot become a leak by being logged or shown.

Cryptographic failures are collapsed to `authenticationFailed`. CryptoKit's
underlying error is not propagated: it tells an attacker more than it tells the
owner, and there is only one correct response either way.

## 8. Localisation

String Catalogs from the start. `OrpheusCore` has its own catalog resolved
against `Bundle.module`; the app target has its own. SwiftUI views use
`LocalizedStringKey` so the catalog picks strings up automatically. English only
today, structured so adding a language needs no code change.

## 9. CI

Every claim about this project is verified on GitHub's `macos-26` runners,
because it is authored on Windows where no Apple toolchain exists.

- Xcode pinned to 26.6, falling back to the newest available Xcode 26.x — the
  image's default Xcode has rotated repeatedly and is not a stable target.
- The simulator destination is resolved at runtime by `simctl`. Hardcoding
  `name=iPhone 17,OS=26.4` breaks silently when GitHub prunes runtimes for disk
  space.
- `build-for-testing` then `test-without-building`, so compilation and execution
  fail distinguishably.
- Warning counts land in the job summary. Reported, not suppressed, not
  promoted to errors.

## 10. Decisions worth revisiting

Recorded honestly, since each is a real tradeoff rather than a settled fact.

- **Metadata is not encrypted.** Buys usable search and sorting; costs titles and
  tags as ciphertext. Encrypted search indexes are possible but a much larger
  design.
- **1 MiB chunks.** Comfortable memory/overhead balance, not a measured optimum.
  Worth profiling in Phase 6 against large video.
- **Fixed HKDF salt.** Sound given full-entropy input key material. A per-vault
  random salt would add little and must then be stored and migrated.
- **XcodeGen.** A build-time dependency to avoid `.pbxproj` conflicts. If Apple
  ships a text-based project format, this stops being necessary.
